## Input/output acceleration (no scientific recipe change)

Before restarting training, raw decoded BGR arrays are saved next to the **local P1B image view** as `.npy`, matching the pinned upstream `BaseDataset.cache_images_to_disk` format. Every cache is compared pixel-for-pixel with upstream `imread`; original dimensions and pixels are retained. The upstream `load_image` already uses these files even with `cache=False`. This avoids repeatedly decoding large PNGs; it does not resize inputs in advance, modify labels, alter augmentation/RNG, or change batch/optimizer settings. Cache hashes and exact equality checks are in `artifacts/decoded_disk_cache.json`. The 35.7 GB train cache fits E:; no cache is placed in original datasets or P1A.

The standard PyPI runtime download was slow and was interrupted before installation; the same pinned wheel is retried through the Tsinghua PyPI mirror. Installation logs are retained. `polars` and `pycocotools` are local runtime dependencies, not modifications to P1A's interpreter packages.

The mirror attempt was also stalled. Final recovery downloaded the **official files.pythonhosted.org wheel** in 1 MiB ranges with eight connections, assembled it locally, and verified SHA256 against the published PyPI JSON metadata before installation. This completed in 51.8 seconds; `artifacts/runtime_download.json` is the authority. Polars 1.35.2 successfully parsed the earlier CSV before the clean pipeline restarted.

The annotation audit found two pairs with identical class/bounding-box vectors but **different polygon text**, rather than proven duplicate polygons. Upstream baseline deduplication uses class/bbox equality; diagnostic/probe annotations preserve both legal polygons as frozen. No val duplicates were found. This affects two train annotations only and is reported as an official-loader difference.

Ensemble probe training stacks independent parameter/Adam states for throughput. Members share the frozen image-order schedule; seeds control initialization and descriptor-bank draws. Inference and latency use each member's standalone linear layers. Three seeds are repeated initialization/control draws, not independent dataset draws. P0 and C3 deliberately replicate the same learned-constant input definition and must remain equal.

## Scientific interpretation boundaries

The first three-architecture schema smoke test matched all 36 pilot GT rasters exactly but exposed nested YOLO26 head output under the pinned source's default external-NMS mode. Before any YOLO26 training/extraction, the launcher/validator now explicitly selects `nms=False` for that generation, and raw extraction sets `head.end2end=True`. This implements the already frozen one-to-one protocol; neither model source nor training loss is patched. See MODEL_AUDIT.md for the property/default-option anchors. YOLO11 training in progress was unaffected.

One synthetic-contract rerun failed in the **provenance wrapper before executing the test**: Windows' default GBK decoding could not read a UTF-8 Git diff containing typographic punctuation. The wrapper now explicitly decodes Git output as UTF-8, and child Python I/O uses UTF-8. This is logging/environment hardening; training already in progress was unaffected. The incomplete attempt directory is retained.

Regularized BCE fits are stable diagnostic solutions, not a proof of optimal IoU or deployable per-instance predictors. Absolute raw coefficient norm is not compared across models. Thirty-epoch clean baselines are a controlled short fine-tuning scope test, not a convergence or leaderboard claim. A negative finite probe result cannot prove that no possible learned mapping exists.
