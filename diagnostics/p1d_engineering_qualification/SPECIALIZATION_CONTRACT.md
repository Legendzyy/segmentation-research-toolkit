# Specialization implementation freeze

Recorded before any P1D specialization outcome, 2026-09-19. The optional M3 clarification received no response during baseline preparation and parity evaluation. Adopt the explicitly offered default: jointly optimize original cv4 and the fixed P1C pure coefficient residual at mask_ratio=1. B1=head/ratio4; M1=head/ratio1; M2=residual-only/ratio4; M3=head+residual/ratio1. M3 changes both head optimization and resolution relative to M2; do not claim a fully isolated resolution interaction. The original config's pending-clarification text is preserved as a historical record; this document resolves that implementation choice before fitting.

The residual remains exactly 10,912 nominal parameters: 136-input Linear64/ReLU/Linear32 plus64 learned constants; only the first32 normalized coefficient slots vary by instance. Unused slots are zero. The final layer starts at zero. No H/P, geometry, scores, classes or image features enter this residual. The existing cv4 in M1/M3 does use its original feature inputs, as in P1C; that is not an added input to the residual.

New cache extraction is checkpoint-specific, training-split-only, losslessly compressed float32. Each cache contains that checkpoint's frozen features, prototypes, TAL assignment, coefficient vectors, and ratio4/ratio1 overlap targets. Train-positive-anchor coefficient statistics belong to that same checkpoint. No reuse of old detector-specific cache outputs. Inherited GT labels are read-only. Extra normalization statistics in inactive P1C geometry slots do not affect the coefficient-only mapping and are omitted.

Specialization lasts15 epochs, accumulation8, float32, AdamW head1e-4/residual1e-3, weight decay1e-4; BN running buffers fixed. Zero initialization and loss/gradient parity against the pinned official loss are required on each starting checkpoint before fitting. A single atomic epoch_state.pt captures all jointly fitted members, full optimizer states, completed epoch, history and RNG states. A partial epoch is discarded on resume; shuffle is a deterministic function of seed and epoch. A completed run is immutable and verified before reuse. Final scheduled epoch only.

`specialization_core.py`, `extract_specialization.py`, and `train_specialization.py` are implemented but only syntax-checked at creation. The real-checkpoint GPU contract is deliberately deferred until ordinary baseline GPU training finishes. Do not treat their syntax check as numerical validation or launch alongside the active P1D baseline.

The proposed warm-start full-network no-augmentation extra15 control still requires a written optimizer/scheduler initialization contract before running. It is additional to, not a replacement for, the mandatory fresh strong+15 standard schedule. Do not choose its schedule after examining specialization outcomes. The baseline recovery.pt stores full precision model/EMA/optimizer/scaler/scheduler/RNG states, but dataloader worker state is not captured; it is not yet a proven bitwise continuation mechanism. Implement and validate recovery conservatively if an actual failure occurs rather than silently using stock fp16 optimizer serialization or changing batch size.
