# 评价与统计契约

## 先定义被测量的量

评价协议至少明确：样本身份与数据角色、坐标系、resize/padding、标签栅格化、mask 解码顺序、score、NMS、最大预测数、匹配规则、空集与 ignore 处理。输入网格上的面积组不能直接叫原像素面积组。

AP 是排序、覆盖、定位及 mask 质量共同产生的完整预测指标。匹配实例上的平均 IoU 回答另一个问题；不能用一个条件均值替代完整 AP。

## coverage 与配对范围

- all-GT 表保留每个合法 GT，包括漏检。没有预测的“原始预测质量”是缺失值，不是自动填零的已定义量。
- 若定义 all-GT utility 并将漏检记零，必须预先命名并说明它与 matched-IoU 是不同 endpoint。
- 同一 GT 的配对分析报告交集大小、各模型自身匹配数、总 GT 数及未匹配原因。
- 多个模型的共同 GT 交集可以提高配对可比性，也改变了估计对象。必须说明条件范围。
- 高 IoU AP 不是边界准确率。边界指标需要单独定义容差、尺度处理、空 mask 和匹配范围。

## oracle 与 native 数值闭合

GT 支持域、GT 引导候选或逐实例拟合使用了部署时不可用的信息。其结果是诊断，不是可部署方法成绩。

以下三项分别检查：优化目标是否收敛；理想算术或线性空间是否能表达；实际推理 dtype 与运算顺序是否实现同一输出。大系数抵消、插值次序、裁剪坐标和零阈值附近翻转都可能让三者分离。

用 BCE 找到的解通常不是 IoU 的经认证最大值。限制支持域 S 时，一个允许任意二值像素的理想预测最多可达到 `|GT ∩ S| / |GT|`（非空 GT），因为选择 `GT ∩ S` 达到该值；实际受限模型不一定能达到它。应区分这个简单集合上界与学习模型的可达结果。

## 统计单位与重复实验

实例嵌套在图像中时，不能无说明地把所有实例当独立样本。图像 cluster bootstrap 应对图像有放回抽样，并携带该图所有实例。还需先确定 estimand：所有实例加权平均与每图等权平均不是同一个量。

模型比较应使用相同的重采样图像索引。若统计的是 AP，每次重采样需按固定评价契约重新组织预测与标注并重算 AP；“每实例 AP 平均”不是替代实现。对重复抽到的图像，应分配独立副本身份，避免评价器将其去重。

训练随机性是另一层变化。报告同 seed 配对差值和全部重复结果；头部 seed、完整训练 seed、恢复轨迹与数据集变化分别命名。两个确认 seed 不足以支持精确总体效应或稳定性断言。本仓库工具只做描述性汇总，不输出 p 值或置信区间。

## 成本与公平性

同 epoch 不等于同训练计算量；同参数量不等于同 latency；没有新增推理层也不等于实测零开销。分别报告训练成本、额外可训练参数、整体参数、推理预处理/模型/后处理的端到端时间、内存，以及硬件、batch、预热、同步与重复次数。

共享 GPU 的进程时间可记录为观察，不能称隔离成本测量。系统比较交代预训练与配方差异；机制比较尽量固定底座、候选身份及评价链路。
