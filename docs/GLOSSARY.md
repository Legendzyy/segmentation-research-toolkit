# 初学者术语表

| 术语 | 在本仓库中的意思 | 容易混淆的地方 |
|---|---|---|
| baseline / control | 回答比较问题的基线与对照 | 弱基线上的增益不等于超过简单强对照 |
| GT | ground truth，评价所采用的标注 | 标注也可能有误差；部署时通常不可见 |
| oracle | 使用特权信息或理想条件的诊断构造 | 不是可部署模型，也不必然是指标严格上界 |
| headroom | 在指定约束下观察到的改善余量 | 不保证该余量能被训练实现 |
| endpoint | 预先定义的最终被比较量 | 某个中间 loss 不自动是任务主指标 |
| AP | average precision，依赖完整预测排序和匹配的评价量 | 脚本接收已算好的 AP，不实现 AP 评价器 |
| IoU | 交并比：交集大小除以并集大小 | matched-IoU 与完整 AP 不是同一个 endpoint |
| pp / 百分点 | fraction 差值乘 100 | 0.50→0.51 是 +1 pp，相对增幅为 2% |
| coverage | 按明确规则被覆盖/匹配的比例与计数 | 必须说明分母及门槛 |
| matched / common-GT | 单模型匹配集合 / 多模型共同匹配的 GT | 条件集合变化会改变所估计的问题 |
| native | 指定原生实现的真实计算路径 | 高精度理想表达式未必给出同样的有限精度输出 |
| replay / parity | 重放保存输入或输出 / 检查两条实现是否一致 | 同一评价器重放证明一致性，不等于独立算法验证 |
| seed | 某个随机过程的种子 | 相同编号不保证不同训练过程共享完全相同随机轨迹 |
| development | 允许用于方案选择和修订的数据/运行角色 | 已见结果不能再冒称未参与设计的确认 |
| confirmation | 冻结比较后进行的确认角色 | 可以是新训练 seed，不一定是新数据集；独立性范围需写清 |
| sealed final / holdout | 项目限定访问和使用边界的保留数据 | 目录名称不等于访问已获授权 |
| freeze / manifest | 固定版本与规则 / 记录身份和哈希的清单 | 哈希不证明科学正确性，也不隐藏内容 |
| STOP / PIVOT | 结束当前方案 / 转向新的问题或设计 | 负结果不等于所有相邻方法都失败 |
| KD | knowledge distillation，知识蒸馏 | 强 teacher 不保证指定迁移损失有用 |

本仓库历史“确认 seed”指未用于当时方案选择的新训练重复，评价仍使用已见 development 视图；不等同在新数据集或未见 final 上验证。详见 [历史结论](RESEARCH_LESSONS.md)。
